# 회원 가입·로그인·JWT 인증 의사결정 기록

## 문제 / 배경

Flutter 모바일 앱이 호출할 REST API 서버에 회원 가입, 로그인, 인증된 요청 식별이 필요하다. 이후 모든 기능(반려동물, 앨범, 메시지)이 "누구의 데이터인가"를 이 단계에 의존한다.

## 검토한 대안

| 주제 | 대안 | 비고 |
| --- | --- | --- |
| 인증 방식 | 서버 세션(쿠키) | 서버 상태 필요, 모바일 앱과 궁합이 약함, CSRF 대응 필요 |
|  | 자체 발급 JWT (선택) | 서버 무상태, 앱이 헤더로 전송 |
|  | 외부 IdP(OAuth2 Resource Server) | 지금 규모에 과함 |
| JWT 라이브러리 | jjwt 0.12.6 (선택) | API가 단순해 학습에 적합 |
|  | spring-security-oauth2-resource-server(Nimbus) | 표준 방식이지만 설정 개념이 늘어 학습 부담 |
| 토큰 구성 | 액세스 토큰만 (선택) | 단순. 유효 30분 |
|  | 액세스 + 리프레시 | 앱이 붙는 시점에 추가 |
| 비밀번호 해시 | BCrypt (선택) | Spring Security 기본, 솔트 내장 |
|  | Argon2 | 더 강하지만 추가 의존성과 튜닝 필요 |
| 테스트 DB | H2 인메모리 (선택) | 빠르고 Docker 불필요 |
|  | Testcontainers PostgreSQL | 운영과 동일하나 Docker 의존, 느림 |
| 필터 등록 | Security 체인에 `new`로 추가 (선택) | 중복 실행 방지 |
|  | `@Component` 등록 | 서블릿 필터로 한 번 더 등록될 수 있음 |

## 선택한 방법과 이유

- 자체 발급 JWT(HS256 명시) + jjwt. 서버 하나가 발급과 검증을 모두 하므로 대칭키로 충분하다.
- 액세스 토큰만 발급한다. 이유: 클라이언트 앱이 아직 없어 재발급 흐름을 검증할 수 없다. 대신 유효시간을 30분으로 짧게 둔다.
- 토큰 payload에는 회원 id(`sub`)만 담는다. 읽을 수 있는 영역이라 개인정보를 넣지 않는다.
- 로그인 실패는 이메일 없음/비밀번호 불일치를 모두 `LOGIN_FAILED`로 통일해 가입 여부 추측을 막는다.
- 이메일은 `trim` + 소문자로 정규화해 저장·조회한다.
- 비밀번호는 ASCII 출력 가능 문자 8~64자로 제한한다. BCrypt가 72바이트까지만 읽기 때문에 글자 수와 바이트 수를 일치시켰다.
- 엔티티를 응답에 쓰지 않고 `MemberResponse`를 쓴다. 해시 노출을 구조적으로 차단한다.
- 필터 체인 안에서 나는 401/403은 `@RestControllerAdvice`가 받지 못하므로, 같은 `ErrorCode`를 쓰는 진입점/거부 처리기를 `SecurityConfig`에 두었다.
- 인증된 요청에서도 컨트롤러가 회원을 조회하므로 탈퇴한 회원의 토큰은 `MEMBER_NOT_FOUND`로 막힌다.

## 고려한 제약 사항

- 서버가 발급한 액세스 토큰을 만료 전에 강제로 폐기할 수 없다. 탈퇴는 위 조회로 막지만, 계정 정지 같은 기능이 생기면 리프레시 토큰 또는 토큰 블랙리스트가 필요하다.
- `pawgeun.jwt.secret`은 기본값이 없다. 로컬·운영 모두 환경변수 `JWT_SECRET`을 주입해야 서버가 뜨며, 저장소에 어떤 키도 커밋하지 않는다. (공개된 기본값으로 운영 서버가 뜨는 사고를 막기 위함)
- 이메일 중복 검사와 저장 사이의 동시 요청은 DB 유니크 제약이 막고, `saveAndFlush`로 받은 `DataIntegrityViolationException`을 409로 변환한다.
- 로그인 시 이메일이 없어도 더미 해시와 BCrypt 비교를 해 응답 시간 차이를 줄였다. 로그인 횟수 제한(rate limit)은 아직 없으며 이후 단계에서 추가한다.
- Docker가 없는 환경에서도 테스트가 돌도록 테스트 DB는 H2(`MODE=PostgreSQL`)다. 운영 DB 고유 기능을 쓰는 시점에는 보장되지 않는다.

## 추후 재검토가 필요하면 (선택)

- Flutter 앱 연동 시: 리프레시 토큰, 토큰 저장 위치(보안 저장소), 로그아웃 처리.
- 데이터가 쌓이기 전: `ddl-auto=update`를 Flyway 마이그레이션으로 교체.
- PostgreSQL 고유 기능 사용 시: Testcontainers 도입.
- 소셜 로그인 도입 시: 회원 테이블에 제공자 정보 추가.
